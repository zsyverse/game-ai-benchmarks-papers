# Independent PCG expansion audit — 2026-09-05

Audit target: the original expansion snapshot #92–111, independently checked against primary arXiv metadata, relevant full-text method/evaluation/limitation sections, and author artifacts. This is a targeted audit, not experiment reproduction or a claim that every earlier PCG entry meets a newly audited uniform standard. GitHub API rate limits were supplemented by author GitHub HTML and raw source inspection. “Closed at check” means no usable official method package verified, not proof of permanent nonexistence. Missing licenses and old dependencies alone do not make available core code Closed.

Outcome: **19 scope keeps, 1 hold** from these 20 candidates. Correct the ZeldaGAN false Closed label, quantum-hardware overclaim, threshold/evaluation caveats, and evidence strength. Original #111 MIPCGRL moves to hold; current public #111 is the separately justified second ChatGPT4PCG benchmark. Thus the public PCG total remains 111.

## Original twenty candidates

1. **#92 Dance Dance Convolution — KEEP.** [Full text](https://arxiv.org/html/1703.06891), §4/Fig.1 and §5.1–5.2: audio → placement → step selection “produces a playable DDR choreography.” Placement perplexity/AUC/F1 and selection perplexity/accuracy are different tasks; do not conflate them with human enjoyment. 2017 ICML identity and [author code](https://github.com/chrisdonahue/ddc) support Open with TensorFlow 0.12.1/legacy caveats; song packs are external inputs.

2. **#93 TaikoNation — KEEP, CORRECT description.** [Full text](https://arxiv.org/html/2107.12506), §3 pipeline and evaluation methodology: 100 training/validation charts (90/10 split), plus 10 held-out songs with corresponding Taiko and DDR human charts. Converts predictions “into a playable format.” Comparison uses binary rhythmic representation, DDC and random noise, not a player-preference study and not an adapted DDC trained directly on Taiko. [Publication DOI](https://doi.org/10.1145/3472538.3472589). [Author release](https://github.com/emily-halina/TaikoNationV1) includes `model.py`, input charts, outputs and multiple TensorFlow checkpoints. Partial is not “almost no code”: `model.py` lists `input_charts` but reads `input_charts_nr`, and loads root `model.tfl` while checkpoints reside under `model/`; unfinished README supplies no repair/reproduction recipe.

3. **#94 Beat-Aligned Spectrogram-to-Sequence — KEEP.** [Full text](https://arxiv.org/html/2311.13687), §2.1/§3.3/Table2/§3.4/Table3: retained 6,781 charts and 2,004 songs, not raw 14,648/3,166. Beat-aligned 4-beat audio with preceding chart tokens generates four-key charts. [Official README](https://github.com/stet-stet/goct_ismir2023) explicitly calls this an **ISMIR2023 LBD extended abstract**, lists splits, preprocessing, training, metric scripts and 300MB external weights. Open code remains appropriate; README says full from-scratch/StepMania chart export is unfinished, and weights/data were not downloaded. Existing `.osu`-template conversion supports chart generation, not a polished universal converter.

4. **#95 Dance Dance ConvLSTM — KEEP, CORRECT comparison.** [Full text](https://arxiv.org/html/2507.01644), §6 and Tables1/A1/A2 distinguish a fixed 0.5 decision threshold from chart-specific F1-max (oracle) thresholds. Comparison uses reimplemented DDC and discusses split/performance differences from its published scores; no direct like-for-like superiority over historical reported scores follows. [Author code](https://github.com/miguelomalley/DDCL) documents `.sm` preprocessing, onset/symbol training and `generate_charts.py`, supporting Open; no license detected, no run performed.

5. **#96 ITGPT — KEEP.** [Full text](https://arxiv.org/html/2607.14148), §3/§5.1/§6: distinct Transformer placement/selection, expanded Fraxtil eight-pack set (253 songs, 952 charts, 584,644 steps), 48 onset slots per beat and 256 step combinations. Evaluate onset, symbolic/top-k/hold metrics and runtime separately. [Author README](https://github.com/miguelomalley/ITGPT) cites this 2026 paper and provides song-pack list, `smfiler.py`, `onset.py`, `sym.py`, `generate_charts.py`, GUI/HF links. Open core source; external music and unexecuted full experiment caveat remain.

6. **#97 Sokoban initial states — KEEP.** [Full text](https://arxiv.org/html/1907.02548), §5 and §7.1/Table1: Beta reverse search generates initial arrangements on supplied board/goal templates; 90 xSokoban problems, up to 34 boxes. Pattern databases, higher-order conflicts and novelty are generator heuristics. Solver hardness is not measured human difficulty; novelty/PDB alone is not uniformly hardest. Closed/unverified is restricted to this artifact search, not a claim that code cannot exist.

7. **#98 Two-step dungeons — KEEP.** [Full text](https://arxiv.org/html/1906.04660), creator/furnisher methods and analysis: floor/wall layout followed by entrance, exit, monsters, traps, potions, portals and treasures in MiniDungeons2. Three creators × three furnishers ×1,000 = **9,000 levels**; layout plus gameplay entities, not isolated rooms. Expressivity and procedural-persona simulations evaluate complete levels. No paper-specific generator package verified in inspected primary links; retain qualified Closed, unlike the corrected ZeldaGAN case below.

8. **#99 ZeldaGAN — KEEP, CORRECT Closed→Open.** [Full text](https://arxiv.org/html/2001.05065), dungeon assembly/repair and user study: 30 participants play three dungeon conditions with six balanced orders. Repair needed in 10/30 GAN and 16/30 grammar-original-room dungeons, averaging under one repaired room. GAN rooms were less organized/more complex; broad enjoyment superiority is unsupported. [Author publication index](https://github.com/schrum2/MM-NEAT/blob/master/PUBLICATIONS.md) explicitly maps the exact CEC2020 paper to [paper-specific experiment](https://github.com/schrum2/MM-NEAT/tree/master/batch/Experiments-2020-CEC-ZeldaGAN), containing study, survey, original/grammar/GAN play scripts. `Zelda_PlayGeneratedGAN.bat` selects `GANLoader`; [loader source](https://github.com/schrum2/MM-NEAT/blob/master/src/main/java/edu/southwestern/tasks/gvgai/zelda/level/GANLoader.java) selects `ZeldaFixedDungeonsAlNoDoors_10000_10.pth` and generates rooms through `ZeldaGANUtil`. This is substantive method code, not an unrelated general repository. Legacy Java/Maven/Python caveat, no fresh reproduction.

9. **#100 NCA — KEEP.** [Full text](https://arxiv.org/html/2109.05489), §3.1–3.2/§4.1–4.2: CMA-ME learns NCA generator weights for maze/Sokoban/Zelda, optimizing validity, reliability and diversity. Generator archive quality and seed stability do not guarantee every generated level is playable. [Author code](https://github.com/smearle/control-pcgrl) identifies the paper and evolution/evaluation configuration; Open with README legacy/cluster caveats.

10. **#101 Path of Destruction — KEEP.** [Full text](https://arxiv.org/html/2202.10184), §II-C/§III–IV: random maps are turned into new levels using learned reverse-destruction actions, not repair-only software. Each trained generator receives 10,000 inference trials across Zelda/DangerDave/Sokoban experiments. Its <10% Hamming duplicate rule differs from exact-duplicate comparisons elsewhere. [Paper-linked repository](https://github.com/matt-quant-heads-io/path_of_destruction) unavailable in this check (raw main/master README404 supplements earlier API404). Keep “Closed at check,” not permanent closed-source inference.

11. **#102 Controllable PoD — KEEP.** [Full text](https://arxiv.org/html/2305.18553), §IV-A versus §IV-B: retain full Zelda levels with player/key/door reachability; separate Lego experiment is not the eligibility basis. §V-A reports 78.86±4.95% playable, but combined playable/unique/diverse filtering yields 24.42±1.93%; these are not interchangeable success rates. No distinct working official method package verified; qualified Closed.

12. **#103 Start Small — KEEP.** [Full text](https://arxiv.org/html/2209.15052), §3/§4.1–4.2/§5.4: autoregressive GFlowNets learn from replayed newly generated playable examples and analyzers/solvers, without an authored training corpus. Not “solver-free.” Evaluation includes three games, multiple seeds and size/control comparisons; reported Sokoban speedups are setting-specific. [Author code](https://github.com/yahiaetman/ms-level-gen) supplies method/game/analyzer/configuration workflows and links weights/samples; Open. [Journal DOI](https://doi.org/10.1016/j.aej.2023.04.019) supports 2022/2023 chronology.

13. **#104 Dungeon MAP-Elites — KEEP, clarify denominators.** [Full text](https://arxiv.org/html/2202.09301), proposed approach and results: feasible room-tree structures integrate keyed locks and enemy distribution into complete prototype levels. **96 played; 74 completed all questions; 121 level plays.** Not 96 completed surveys and not a controlled A/B superiority experiment. Paper links an [author parameter-results spreadsheet](https://docs.google.com/spreadsheets/d/1QmKPv8KyoavYy0jLWxQi07-itoTBv8VlJ8447X78Hvk), but no method implementation was verified; the link alone does not establish Open generator status.

14. **#105 High Dimensional PCG — KEEP, CORRECT evaluation.** [Full text](https://arxiv.org/html/2602.18943), §5.1/Figs7/9/10 and Unity grounding: three algorithms per Space/Time axis output plans grounded from JSON in Unity with colliders, movement/controller and endpoint trigger. Explicit quote: “This Unity scene supports direct human play; however, all quantitative results in Sec.5.1 are computed from solver-generated trajectories rather than from user studies.” Thus not framework-only, but demonstrations do not establish user enjoyment or joint-mechanic composition. Solver certification is a witness route, not elimination of all unintended shortcuts. No released toolchain verified; draft ACM placeholder DOI is not publication evidence.

15. **#106 FPS MAP-Elites — KEEP.** [Full text](https://arxiv.org/html/2605.30570), §3–6: four map representations, sliding-boundary MAP-Elites and bot deathmatch simulation in ProjectArena. Do not substitute Cube2 from related work for this runtime. [Linked generator](https://github.com/SimoDedo/MAPElites_FPS_Maps) unavailable in raw main/master README checks; API access later rate-limited, so no fresh API404 claim. Separate [ProjectArena runtime](https://github.com/MarcoBallabio/ProjectArena) is not the complete generator experiment. Retain earlier “Closed at check” with date-limited evidence.

16. **#107 Sokoban diffusion — KEEP.** [Full text](https://arxiv.org/html/2608.15958), §2.3/§3: trains on 450,000 Boxoban puzzles; evaluation uses solver on fresh batches. 77.4% generated solvability differs from the **94.5% of remaining failures** repairable by removing one wall. “Without solver” concerns training/sampling, not evaluation or the released export pipeline. [Author release](https://github.com/sinabaghal/SokobanPlayground) includes inference, `model.pt` and play export, not verified full training/evaluation reproducibility. Partial, license unverified.

17. **#108 Emotional-arc generation — KEEP.** [Full text](https://arxiv.org/html/2508.02132), Figs1–2, user study/Table1: story graphs instantiate connected Unity/WebGL ARPG rooms, entities, attributes and sprites, not just narrative/assets. **16 participants; 13/16 (81.25%)** identify the arc. Bootstrap confidence intervals do not remove small/homogeneous sample limitations; exploratory enjoyment/coherence claims only. No official generator/build/study-data release verified.

18. **#109 Multi-agent PCGRL — KEEP.** [Full text](https://arxiv.org/html/2510.04862), experiment domains/Table1: cooperative editing agents generate binary maps and dungeon levels with player/key/door reachability and enemy constraints; they are not game-playing policies. Ten training runs ×50 evaluation episodes per condition; unseen square/rectangular sizes test transfer. Reward is a generation-quality proxy, not human enjoyment. [Shared author implementation](https://github.com/smearle/pcgrl-jax) has training/sweep/evaluation workflows; exact multi-agent paper snapshot was not recovered in this pass, so preserve the explicit snapshot caveat rather than claiming experiment reproduction.

19. **#110 QRC — KEEP, CORRECT hardware/method/artifact.** [Full text](https://arxiv.org/html/2505.13287), introduction/§IV/Fig7: “we resort to simulating the quantum circuit on non-quantum computers and leave the training and generation on real quantum hardware for later works.” The [Roblox obby](https://roblox.com/games/104964767415370/Nerii) has platforms, gaps, enemies, checkpoints and ordered interactive features; game scope is concrete. Hardware timing/parallel generation is prospective, not demonstrated real-device deployment or quantum advantage. Broken sequences can still be ~36% at six qubits; Markov/uncorrelated baselines are not SOTA GAN comparisons. [Paper-specific OpenData](https://github.com/moth-quantum/OpenData/tree/main/Level_Generation_with_Quantum_Reservoir_Computing) contains Data/Figures/data.ipynb; notebook imports `/Users/mothp/Python_codes/Nerii-4/archeo/`, `archeo.utils`, `MarioLvlEncoder`, `SequenceMapping`, `MeasurementsSuite` unavailable in that release. Partial is substantiated by missing core local modules, not vague repository uncertainty. [IEEE CG&A DOI](https://doi.org/10.1109/MCG.2025.3591956).

20. **Original #111 MIPCGRL — HOLD, not counted.** [Full text](https://arxiv.org/html/2508.09193), §III/experimental setup/§VI-B: current title is **Multi-Objective Instruction-Aware Representation Learning in Procedural Content Generation RL**; 2025 v1 and 2026 v3, not a fabricated paper. Objective-aware classifier/regression encoders support instruction-conditioned editing; targets are regions, path length, wall count, bat count and bat direction. Aggregate 13.2% improvement versus IPC is distinct from 8.7% single-objective and 25.4% versus ContGoal; held-out subsets still incur losses. [Official config](https://github.com/k-shyun/MIPCGRL/blob/main/conf/config.py) defaults to `problem="dungeon3"`; [domain](https://github.com/k-shyun/MIPCGRL/blob/main/envs/probs/dungeon3.py) enumerates BORDER/EMPTY/WALL/BAT without player/start/goal and has placeholder `get_curr_stats`. Primary evidence inspected does not establish generated outputs loaded into a playable task or valid objective/interaction rules. Under SCOPE's ambiguous-evidence rule, hold until primary generation→playable-task evidence or another demonstrated qualifying domain is found. This is not a claim that the research lacks value, is absolutely unplayable, or that every legacy binary-PCGRL entry has been re-audited. Meaningful train/encoder/evaluation code exists; artifact availability does not settle scope.

## Two previously conflated publication families

- **ChatGPT4PCG 2023 versus 2024: separate formal protocols.** [2023 full text](https://arxiv.org/html/2303.15662), §III and preliminary experiments: single reusable single-turn prompt, stability/similarity; proposed 26 letters ×10 trials versus actual preliminary 5 variants ×3 letters ×10=150. [2024 full text](https://arxiv.org/html/2403.02610), abstract/introduction/evaluation: Python program submissions allow multi-turn/control flow; adds diversity, font-trained classifier and altered function signatures with ablations. [Code/raw data](https://github.com/chatgpt4pcg/experiments-2024). Keep #75 for2023 and assign current #111 to2024; distinct evaluation contracts justify separate benchmark records, not superficial version inflation.
- **ChatPCG versus PCGRLLM: distinct outputs, only later work retained.** [ChatPCG full text](https://arxiv.org/html/2406.11875), RaidEnvII and framework sections: skill/character settings adjusted by RL, with conceptual reward design and game-log self-alignment. [Official prompts](https://github.com/bic4907/ChatPCG) explicitly list health/armor/speed/range/cooldown/damage and state “action is adjustment of the game setting values.” This is standalone parameter tuning under current SCOPE, not new executable rule structure, so do not count it. [PCGRLLM full text](https://arxiv.org/html/2502.10906), architecture, experiment environment, key-door scenario and AppendixB: adds trained-policy-output feedback outer loop and tests generated 2D layouts including player→key→locked door→treasure constraints by flood-fill. Retain #81 solely for2025/2026 PCGRLLM; no longer describe ChatPCG2024 as the same story-level paper. Printed tile-count wording is internally inconsistent; avoid reproducing an exact tile count.
