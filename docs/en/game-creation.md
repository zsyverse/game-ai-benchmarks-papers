# Game-creation benchmarks and papers

Source cutoff: **2026-08-29**. Reproducibility labels mean: **Yes** — public tasks/data plus a runnable evaluator or training/inference code make the same score definition obtainable in principle; **Partial** — some artifacts are public, but tasks, hidden tests, generated outputs, a complete scorer, or required assets are missing; **No** — there is no public, fixed benchmark protocol plus artifacts, so the work should not be treated as a reproducible leaderboard.

## Caveats

1. **A playable demo is not a benchmark.** Without fixed tasks and an evaluator, Genie, GameNGen, Oasis, Hunyuan-GameCraft, and similar systems belong in the paper/tool section, not on a benchmark leaderboard.
2. **World models and game-building agents solve different tasks.** The former predict pixels or latents under actions; the latter generate or modify code, scenes, and assets and must pass engine/runtime tests. Keep their rankings separate.
3. **Separate model-judge scores from deterministic tests.** GameDevBench and GameEngineBench use more repeatable behavioral tests; GameCraft-Bench and V-GameGym cover richer visual/experience dimensions but depend on the judge model and version.
4. **Recheck data and licensing at use time.** YouTube-ID datasets such as OGameData can suffer link rot; Unreal, EOS, Atari, and other resources may require engine, SDK, ROM, or asset licenses.
5. **Do not label GameXpert-Bench or JamBench “downloadable” at this cutoff.** The former repository explicitly says release artifacts are pending; the latter has no verifiable official artifact URL.
